# ColorCAN CANプロトコル v1

## フレーム共通仕様

| 項目 | 値 |
|---|---|
| ビットレート | 1,000,000 bit/s |
| フレーム形式 | Classic CAN、標準11-bit ID（IDE = 0）、データフレーム（RTR = 0） |
| DLC | 8 |
| バイト順 | リトルエンディアン。複数バイトの値は下位バイトから送信 |
| ノード番号 | 0〜7。起動時にID用DIPを読み取り、CAN IDの下位3ビットに格納 |

受信側はID範囲、標準データフレーム、DLCを確認してからデコードします。`can_id & 0x07` がノード番号です。受信ツールで使える [ColorCAN.dbc](ColorCAN.dbc) に全16フレームを定義しています。

| ノード番号 | RGBC | ハートビート |
|---:|---|---|
| 0 | `0x240` | `0x248` |
| 1 | `0x241` | `0x249` |
| 2 | `0x242` | `0x24A` |
| 3 | `0x243` | `0x24B` |
| 4 | `0x244` | `0x24C` |
| 5 | `0x245` | `0x24D` |
| 6 | `0x246` | `0x24E` |
| 7 | `0x247` | `0x24F` |

## RGBC測定値

100 msごとにTCS34725FNを読み取り、有効な測定値を取得できた回だけ送信を試みます。値はすべてセンサの生カウント（符号なし16-bit、倍率1、オフセット0）です。Clearはセンサのクリアチャンネル値です。色分類が必要な場合は受信側で行います。

| バイト（0始まり） | 内容 |
|---|---|
| 0–1 | Red |
| 2–3 | Green |
| 4–5 | Blue |
| 6–7 | Clear |

ノード5のデコード例。

```text
ID 0x245  DLC 8  DATA 58 00 64 00 7D 00 38 01
R=88  G=100  B=125  Clear=312
```

## ハートビート

起動直後と、その後は約1秒ごとに送信を試みます。センサ状態フラグが変化した回も送信を試み、そこから次の約1秒を数えます。測定値を取得できない間もハートビートは送信対象です。

| バイト（0始まり） | 型 | 内容 |
|---|---|---|
| 0 | 符号なし8-bit | プロトコル版。現行は `0x01` |
| 1 | ビットフラグ | 直近のセンサ読み取り状態 |
| 2–3 | 符号なし16-bit | 起動後の測定成功回数。65535の次は0。CAN送信結果と独立して加算 |
| 4–7 | 符号なし32-bit | 起動後の経過時間。単位はms。約49.7日で0に戻る |

| バイト1のビット | マスク | 1の意味 |
|---:|---|---|
| 0 | `0x01` | 有効なRGBCを読み取れた |
| 1 | `0x02` | I²C通信、またはセンサ初期化に失敗した |
| 2 | `0x04` | センサIDが期待値 `0x44` と一致しなかった |
| 3 | `0x08` | R・G・B・Clearのいずれかが飽和判定値（現設定で21,504）以上 |
| 4–7 | `0xF0` | 予約。v1では0 |

ノード5のデコード例。

```text
ID 0x24D  DLC 8  DATA 01 01 34 12 78 56 34 12
版=1  状態=測定有効  測定成功回数=4660  起動後=305419896 ms
```

## 受信側での状態管理

- RGBCとハートビートの最終受信時刻をノードごとに保持します。IRC27 ParameterGatewayでは、RGBCが350 ms、ハートビートが3秒更新されない場合に更新切れとして扱います。
- ハートビートの版が1のときに上のフラグを解釈します。測定有効ビットが0なら、最新の測定値を待ちます。飽和したRGBCも測定有効ビットを立てて送るため、飽和データを使うかどうかは受信側で判断します。
- ACKはClassic CANフレーム内のACKスロットです。ColorCANの状態や稼働を確認するにはハートビートを監視します。
